# AI ChatNavigator 1.0.3

本版本修复目录更新、消息匹配和跳转取消。运行时继续使用原生 JavaScript，仅申请 `storage` 权限，所有聊天处理仍在本地完成。

## 行为变化

1. 目录复用原有条目，只更新增删改内容。流式回复不会反复重建提问列表，键盘焦点和目录滚动位置会保留。
2. 点击提问后立即定位；用户滚动、触摸、按滚动键、再次点击、关闭侧栏或切换会话都会取消待执行的跳转。最多进行一次短时位置纠正，不再持续固定滚动位置。
3. 优先使用唯一消息 ID；没有 ID 时只接受仍在当前消息列表中的同一节点。提问被编辑、节点失效或无法唯一匹配时显示提示，不按重复文本和数组下标猜测目标。
4. 目录明确显示已加载提问数量，不再用 Q1/Q2 暗示完整对话中的顺序。暂时卸载或删除的消息会移出目录，不自动抓取或保存历史；用户滚动加载更多消息后，目录随之更新。
5. 加入明确的加载、空对话和错误提示及 Retry 操作；容器整体替换后可以重新绑定。清除聊天内容调试日志，并让 popup 区分可用、加载中和不支持的页面。

目录条目和打开入口改为按钮，支持基本 Tab/Enter 操作；减少动画的系统设置也会被尊重。搜索、收藏、跨会话阅读恢复、可调面板和原生 Side Panel 不包含在本版本内。

运行逻辑测试：

```sh

```

浏览器回归保存在 `tests/browser.cjs`。需准备可由 Node 加载的 Playwright 和 Chrome；测试只在临时配置中加载扩展并拦截请求返回模拟页面，不使用日常浏览器配置。可通过 `ACN_EXTENSION_DIR` 指向已构建目录，截图与结果默认写入系统临时目录。

## 安装与发布

构建命令：

```sh
node scripts/build-chrome-release.mjs
```

构建脚本先检查 JavaScript 语法并运行逻辑测试，再按文件允许名单打包。旧图标、文档、测试、日志和工作区文件不会进入运行包。输出包含 ZIP、SHA-256、各源文件校验值及 Git 状态记录，未打包目录为 `dist/chrome-v1.0.3/`。

现有 1.0.2 ZIP 保留在本地。1.0.3 安装包在代码提交前构建，因此 provenance 中的 Git HEAD 和工作区状态记录的是构建时的状态；包内文件可通过 sourceSha256 与本次提交的源码逐一核对。GitHub 提交包含 1.0.3 源码、测试、文档及安装包，未包含无关录像、临时输出和旧素材。构建脚本拒绝覆盖同版本发布包。

本地验证步骤：

1. 打开 `chrome://extensions`，开启开发者模式。
2. 选择“加载已解压的扩展程序”，打开 `dist/chrome-v1.0.3/`；若已加载的是当前项目根目录，则点击对应扩展的刷新按钮即可。
3. 刷新已有聊天标签页，打开一条长对话，依次验证目录点击与滚轮接管。

## 支持边界

普通聊天仍按各站 adapter 的路由规则启用。项目专属、自定义助手、共享、agent/work 等规则之外的路径没有新增支持承诺。目录仅覆盖当前已加载的提问；历史尚未加载时不显示完整总数，也不后台遍历整段聊天。

浏览器自动升级扩展后，已打开页面可能需要刷新才能使用新内容脚本；popup 会在无法连接时提示刷新或打开支持的聊天页面。构建完成不等于已上传或通过 Chrome Web Store 审核。
