# AI ChatNavigator 1.0.2 升级评估

评估日期：2026-09-20。范围：本地 1.0.2 发布包、当前运行代码、Chrome 扩展平台及三站官方更新。本文是升级规划，没有修改扩展运行代码。

## 1. 建议先做什么

先发布 1.0.3，解决目录和跳转的可靠性；1.1 再加入对话内搜索、收藏定位、阅读位置恢复。Chrome 原生 Side Panel 先做小规模原型验证，再决定是否发布。

产品定位建议改为：**在 ChatGPT、Claude、Gemini 中，用同一套操作找回长对话里的具体内容。**

理由：ChatGPT 已提供原生长对话目录。只增加提问目录的差异正在缩小。三站一致的操作、可辨认的条目、准确定位与可控的阅读恢复更值得投入。此定位是基于功能变化的产品判断，尚未通过用户访谈或使用数据验证。

| 核对项 | 结果 |

| 发布包一致性 | 包内 JS、CSS、popup、图标与工作区逐字节一致；manifest 仅排版不同，解析后相等 |

已有能力值得保留：实时提问目录、点击跳转、当前条目高亮、固定与收起、浅深色样式、本地处理。无需为此次升级重写为 React、引入后端或接入大模型 API。

`chatgpt.js` 当前 928 行，Claude/Gemini adapter 分别为 44/45 行。行数不是质量指标，但 ChatGPT 已积累大量等待、重试、日志和滚动纠正逻辑，适合拆出独立导航控制器，统一三站的生命周期约定。

## 4. 五项优先改进

### P0-A：目录要区分“已加载内容”和“完整对话”

**代码事实：** `content/sidebar.js:412` 每次用传入 messages 完全替换目录，再从 Q1 编号。三个 adapter 主要读取当前 DOM。ChatGPT 虽有历史加载重试，但只有点击已有条目、重新查找失败时才触发，不能自动建立从未加载过的消息目录。

**最小复现：** 输入两条消息后，只保留第二条再次调用 `updateEntries()`，第二条变为 `Q1: Second prompt`。这是隔离逻辑复现，不是三站线上故障复现。

**建议：** 建立以平台、会话、当前分支和消息身份区分的内存索引；元素引用只是临时定位手段。优先使用稳定消息 ID，缺少 ID 时结合邻近内容校验，不能把位置索引当成稳定身份。

**边界：** 不能简单累加所有历史节点，否则编辑、删除、切换分支后会留下旧条目。应区分节点暂时卸载和消息确实被移除；无法区分时标注未确认，不猜测完整顺序。

**用户行为：** 显示“已索引 N 条，可能还有未加载历史”。默认被动收集已加载内容；“加载更多历史”由用户触发、可取消，并保留原阅读位置。没有完整性证据时不显示全对话总数，也不承诺全文搜索。

### P0-B：跳转不能猜错位置，也不能阻止用户滚动

**代码事实：** `chatgpt.js:748` 在相同文本存在多个匹配时，用全局 index 截断选择重复项。隔离复现中，原 ID 已不存在、index 为 4、存在两个重复文本时，函数返回第二个重复项，而非报告无法确定。

`chatgpt.js:306` 的滚动固定仅监听 scroll，没有 wheel、touch、键盘取消处理。跳转时先等待页面稳定，长对话首轮最长等待配置为 6500ms。`content.js` 切会话会清理公共 observer，但没有统一调用 adapter 导航取消钩子。

**建议：** 每次导航绑定单调递增的请求 ID 和会话 generation；新点击、用户主动滚动、路由切换都取消旧请求。ID 或上下文无法唯一匹配时，保留原阅读位置并提示重试。移除常态下的强制位置固定，只保留有时限、可取消的必要纠偏。

**验收：** 重复提问不跳错；连续点击以最后一次为准；切会话后旧任务不能再滚动；手动滚轮立即接管。真实页面上的回弹程度仍需实测。

### P1-C：流式回复时只更新变化的内容

**代码事实：** `observer.js:11` 监听子树所有属性、文本和节点变化，相关回调直接扫描消息。`content.js:77` 先 `setState(READY)`，再 `updateEntries()`；两条路径都可能完整重建目录。

**隔离复现：** 同样的 2 条提问连续更新 100 次，实际创建 400 个新目录条目。这个数字说明重复工作，不代表已测得 CPU 占用或页面帧率。

**建议：** 过滤插件自身变更与无关属性；同一帧合并更新；比较消息签名，只更新增删改条目；READY 状态不重复渲染。复用条目节点，保留焦点与目录滚动位置。长列表是否需要虚拟化，以实测决定。

**验收：** 助手持续输出且提问列表未变化时，目录条目创建/删除次数为 0；新提问只新增对应节点；不靠每次 `scrollIntoView()` 把用户正在浏览的目录拉回当前条目。

### P1-D：把兼容性拆到具体场景，并补齐恢复状态

**代码事实：** ChatGPT 只匹配 `/`、`/c/`；Claude 只匹配 `/`、`/new`、`/chat/`；Gemini 只匹配可含账号前缀的 `/app/`。合成路径测试证实其他模式不匹配，但未验证这些合成路径都是当前真实入口。

普通聊天、项目内聊天、自定义助手/Gems、只读分享、研究与文档侧栏应分别列入验证矩阵。不要为了覆盖入口改成全域无条件显示；设置页、登录页等仍应排除。

当前观察器绑定的容器若在同一路径下被整体替换，缺少明确的重新绑定机制；EMPTY 与尚未加载完成的判断也较粗。需区分加载中、空对话、部分索引、提取失败、不支持的页面，并提供重试和简短说明。

`observer.js` 在内容脚本里包装 `history.pushState`/`replaceState`，但 Chrome 内容脚本默认位于 isolated world，不能把这种包装当成可靠的页面路由钩子。保留经过验证的 URL 检测后备，结合页面生命周期与容器健康检查；若采用 `webNavigation`，需说明新增权限的实际收益。[内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

### P1/P2-E：给用户更强的找回能力，并改善面板操作

优先做以下五项，其中前两项构成 1.1 的主要新增价值：

1. **对话内搜索：** 首先搜索已索引提问，匹配结果可直接跳转；后续再扩展到已加载回答与标题，并标明搜索范围。
2. **收藏与阅读位置：** 为具体提问添加本地书签、可选短标题；恢复阅读位置用明确入口，不自动抢滚动。临时/隐私对话默认不持久化内容，手动保存需说明行为。
3. **条目可辨认：** 允许两行预览、展开完整提问、显示附件或图片占位说明；避免只出现 Q7 而无可读信息。当前固定前 50 字且 CSS 单行截断，不利于区分相似开头。
4. **面板可控制：** 左右位置、宽高与每站偏好；在原生目录、Artifacts、Canvas、全屏文档存在时可收起。原生目录检测失败时提供手动选择，不自动隐藏官网控件。
5. **键盘与主题：** 目录使用可聚焦按钮或链接；支持打开/关闭、搜索焦点、方向键/Enter/Escape，避免抢占输入框及官网快捷键；加入 `aria-current`、动态主题更新、减少动画支持与中英文文案。

当前 CSS 将面板固定为 196×240px、放在右侧最高层级，存在覆盖其他工具的风险，但此次没有截图证实具体遮挡。`updateTheme()` 当前只在创建时调用；条目与触发器是 div，缺少键盘操作约定。关闭状态仅在内存中，保存函数只写 `acn_pinned`，切换会话时会重置关闭状态；需明确“本会话关闭”和“此站默认关闭”的区别。

## 5. 分版本交付

时间是单人开发的初步估算，假设可用测试账号和代表性对话已准备好；不含 Chrome 商店审核等待时间。

| 阶段 | 建议范围 | 完成标准 | 预计时间 |
|---|---|---|---|
| 1.0.3：稳定性 | 索引完整性提示、重复项匹配、导航取消、目录增量更新、容器重绑与错误重试；三站基础回归 | 普通聊天支持清单内场景不跳错、不抢滚动；流式输出不重建目录；证据不足的历史明确提示 | 5–7 个工作日 |
| 1.1：找回内容 | 已索引提问搜索、本地收藏与短标题、手动恢复阅读位置、键盘操作、面板大小/位置、原生目录共存与基础本地化 | 代表性长对话中，完成“找某条提问→定位→收藏→重新找到”；相似提问可区分，键盘可完成主流程 | 5–8 个工作日 |
| 1.2 候选：原生 Side Panel | 对比浮动面板与原生面板原型，验证 tab 隔离、切换与宽度；先不承诺全面迁移 | 在 Artifacts/Canvas/原生侧栏场景下比较遮挡、操作步数和可读性，再决定保留双模式还是单模式 | 原型 2–3 个工作日，正式交付另估 |

1.0.3 同时完成的发布基础工作：

1. 默认关闭内容日志。`sidebar.js:360` 和 `chatgpt.js:682` 会记录 label 与前 80 字提问；诊断只保留结构、计数、耗时与错误码，不默认输出聊天文本。这是本地日志问题，未发现向外上传的代码。
2. 增加少量有意义的 adapter/导航回归用例与发布检查；开发依赖不必进入运行包，继续保留轻量运行时。
3. 将经过确认的 1.0.2 基线整理为可追溯提交/标签，补发布说明和包校验值，防止工作区、源码标签和上传包分离；本次不替用户提交既有改动。
4. 调整构建允许名单，避免旧图标等额外资源进入包；增加 manifest/语法/必要文件检查。
5. 发布前更新支持范围与已知限制。书签上线后说明存储内容、删除方式和临时对话行为，保持本地优先。

暂不投入：跨平台自动搬运全部聊天、自动 AI 总结、云同步、账户体系、更多平台接入、通过私有接口抓取完整历史。它们需要额外维护与隐私设计，且不能解决当前的定位可靠性问题。回答标题导航与 Markdown 片段导出保留为后续候选，先验证需求。

## 6. 测试与证据计划

| 场景组 | 需要覆盖的操作 | 判定方式 |
|---|---|---|
| 消息与索引 | 长对话历史补载、节点替换、重复提问、编辑/分支、纯附件提问 | 不误合并、不把旧分支混入；完整性状态真实，身份匹配失败时不猜 |
| 导航与路由 | 第一/中间/最后条目、连续点击、手动中断、切会话、后退前进 | 目标正确；旧任务已取消；焦点与阅读位置不被后台任务抢走 |
| 页面场景 | 三站普通聊天，项目/Gems；打开文档或 artifacts；临时聊天 | 按实际验证结果标记支持、部分支持或不支持；未支持入口不误报为空聊天 |
| UI 与效率 | 30/100/300 条提问，流式输出；浅深色切换，窄窗口，纯键盘 | 无变化时零条目重建；保留焦点与目录滚动；记录实际耗时，不虚构性能提升 |
| 扩展发布 | 解压加载、从旧版升级、旧标签页、tab 切换、权限与日志 | popup 能解释需刷新页面等状态；默认无内容日志；打包内容可追溯 |

初步性能目标：100 条已加载提问的搜索响应 P95 小于 100ms；可定位的已加载消息跳转 P95 小于 500ms；用户滚动取消在下一次输入处理/渲染周期生效。以上是待测目标，需记录 Chrome 版本、硬件和页面状态后评估，不是 1.0.2 已达到的数据。

这轮完成的检查：发布包逐文件对比、manifest 语义对比、adapter 合成路径测试、重复文本匹配复现、目录重复渲染与缩减列表复现、官方来源核查。未安装依赖，未运行构建覆盖现有包，未修改运行代码。

这轮未完成的检查：登录态三站实页、原生目录实际出现条件、DOM 选择器与页面路由、性能录制、截图和无障碍实操。`ego-browser` 在同一任务空间先出现 `PageNavigationTimeoutError`，随后页面状态读取出现 `CdpRequestTimeoutError: Runtime.evaluate`。因此本文不宣称已经完成真实页面 UX 审计或三站兼容性验证。
